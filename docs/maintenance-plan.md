# 回放链路检查与改造顺序

2026-09-24 基于当前 V2 代码和真实 1 GiB BLF 压测。普通测试覆盖排序、重叠、CAN FD、DBC 解码、SQLite、界面回放、项目持久化；大文件测试覆盖完整预检、后台回放和界面回放。压测数据见 `tests/test_large_blf.py`，运行时输出时间和内存。本机结果：1.00 GiB、9,260,000 帧，生成 25.7 s、预检 27.3 s、后台回放 36.2 s、界面回放 42.2 s，进程工作集相对基线峰值增加 24.4 MiB。

## 已处理

1. `prepare_sequence` 和 `ScanWorker` 的文件排序、重叠校验曾各写一份，现统一在 `core.validate_sequence`，同一边界规则应用于同步与异步导入。
2. `ReplayWorker` 曾在每写满 2000 个样本时向界面发进度事件。信号密集时会形成大量跨线程事件；现在写盘批次与最长 250 ms 的界面通知间隔分别控制。测试覆盖 4500 个连续信号样本、分批提交、仅一次结束通知。
3. 失败的回放曾在 `MainWindow._worker_finished` 中满足“有未缓存信号”条件时启动补画，导致同一错误反复重读大 BLF。现在只在成功完成后自动补画。
4. 开发测试依赖单独列在 `requirements-dev.txt`；运行依赖仍由 `requirements.txt` 给出。

## 风险与建议顺序

| 顺序 | 风险与证据 | 建议改造及验证 |
| --- | --- | --- |
| 1 | 时间轴跳转、补画新信号均从 BLF 开头顺序重读；`ReplayWorker.run` 用 `start_at` 过滤帧，却没有磁盘定位。添加新 BLF 时 `ScanWorker` 也会重扫所有已导入文件。1 GiB 文件的这些操作仍需再次读取全部容器。 | 为 BLF 容器建立持久化的时间/文件偏移索引，并复用未变化文件的预检结果；用文件间空白、容器边界、时间戳相等及文件被外部修改的用例验证。 |
| 2 | `inspect_file` 将每个 `(channel, frame_id, extended)` 放入 `max_payloads`，随后复制为 `FileInfo.max_payloads`；异常多的扩展 ID 会让预检元数据随唯一 ID 数增长。 | 将报文长度元数据写入磁盘索引或按 DBC 所需 ID 查询；用百万不同扩展 ID 的生成数据测峰值内存与缺失信号提示。 |
| 3 | `app.py` 同时维护项目、信号选择、线程生命周期、原始报文表和绘图刷新；大量状态靠 Qt 回调隐式传递。 | 先抽出回放状态/缓存生命周期，再抽项目与信号选择控制器；围绕停止、失败、跳转、补画编写状态转换测试后搬迁代码。 |
| 4 | `core.py` 中指纹、单位、缺失信号原因重复执行 DBC 报文/信号查找；同一标识的标准帧/扩展帧检查并不完全一致。 | 建立一个带帧格式校验的信号定义查找函数，统一三个调用点；补同 ID 不同帧格式、截断帧、复用信号名测试。 |
| 5 | SQLite 缓存用 `(signal, timestamp, value)` 作主键并每 2000 点提交。相同时间、相同值的重复帧会折叠；大量连续信号会增加缓存体积及写盘时间。 | 明确波形是否需要保留重复帧；若需要，加入序号键。随后测 40 信号、密集采样的缓存大小与视窗查询延迟。 |
| 6 | 依赖只声明兼容范围，没有锁定完整环境；原有 `.venv` 指向已失效的 Windows Store Python，无法直接复现运行。 | 提供可重建的开发环境与 Windows CI，记录 Python 和依赖版本；按支持的 Python 版本跑普通及可选大文件用例。 |

原单通道大文件压测使用无压缩、64 字节 CAN FD 帧，其中每 1000 帧有一帧需要 DBC 解码。该分布验证顺序读取和有限信号缓存；高压缩率、损坏容器、40 信号密集写入及真实设备采集文件仍需单独验证。

## 多通道大文件补测

`scripts/generate_multichannel_blf.py` 可重复生成 1 GiB BLF、通道 1/2 的独立 DBC 和帧分布清单。通道 1/2 用同一个标准帧 ID 与同名信号，但物理值分别为 7 和 14；通道 3 未映射 DBC，仍包含同 ID 帧。文件混合经典 CAN 与 CAN FD。普通测试用 2 MiB 样本覆盖通道隔离；可选大文件测试覆盖完整预检、后台 SQLite 样本及界面回放。

本机补测：1.00 GiB、9,830,000 帧，通道 1/2/3 分别约 327.7 万帧，经典 CAN 约 97.3 万帧。预检 28.6 s、后台回放 39.1 s、界面回放 44.2 s，进程工作集相对基线峰值增加 26.0 MiB。测试数据保存在 `.test-data/multichannel-1g.blf` 及同目录的两份 DBC 和 manifest；该目录被 Git 忽略，可按需重新生成。
