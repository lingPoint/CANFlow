# CANFlow 3.1.0 多窗口重构验证

## 实现范围

按已确认的多窗口分析方案实现正式 PySide6 程序：顶部操作，纵向多个分析窗口，左侧信号表、右侧浅色网格波形。移除独立配置页和波形下方控制区。文件、DBC、信号、显示设置、原始报文通过顶部入口打开所属分析窗口的非模态面板。

- `canflow/workspace.py`：管理窗口列表、当前窗口、顶部命令与关闭流程。默认两个窗口；可新增，至少保留一个。
- `canflow/app.py` 的 `AnalysisWindow`：独立持有文件序列、DBC 映射、已选信号、后台任务、SQLite 缓存、游标和测量标记。
- `canflow/session_ui.py`：构建分析画布、工具栏及配置面板，统一浅色外观。
- `canflow/chart.py`：保留独立 Y 轴轨道、真实采样测量和视野抽样；加入浅色高对比配色与完整网格。
- 保留原有双文件片段对比入口、项目格式及信号组格式。信号组库共享，操作前重新读取，避免不同窗口用旧列表覆盖新组。

## 交互与任务生命周期

顶部分析工具栏挂载当前窗口自己的控件，不把文件、任务或测量状态复制到全局变量。点击窗口内控件、波形或配置面板，会识别它的所属窗口。下拉框和 Ctrl+Tab 也能切换操作对象。

导入和修改 DBC 有忙碌状态检查。原始报文回放不要求 DBC；已回放数据追加信号仍由原有补画逻辑处理。回放本身不会把未改动项目标记为脏数据，失败状态不会被后续结束通知覆盖为“已停止”。

关闭单个窗口时先处理未保存项目，然后停止并等待该窗口的任务，最后释放缓存。关闭整个程序时先检查全部项目；任一取消都不销毁窗口。关闭后的排队预检/DBC 结果不能重新填充界面或重建缓存。

## 验证

- 完整测试：**94 passed, 3 skipped**。包括原有解码、缓存、项目、信号组、补画、双文件对比等测试，以及 9 个多窗口集成场景。
- 两份生成的真实 BLF 同时回放，验证同名信号的样本数和值不同且缓存独立。
- 验证点击/键盘/配置面板切换归属、当前窗口导入、暂停与关闭、取消关闭、项目保存路由、共享组库、多个窗口滚动、排队结果清理和失败状态。
- 元数据缓存测试显式推进测试文件 mtime，消除 Windows 快速同尺寸改写可能共享时间戳造成的偶发失败；生产缓存策略未改变。
- 实际 Qt 渲染截图：`workspace-1600.png`（1600×1024）、`workspace-1280.png`（1280×800）、`workspace-1000.png`（1000×660）、`dbc-editor.png`、`signal-editor.png`。
- 截图由 `python -m scripts.capture_redesign` 生成，采用生成的 CAN 数据，包含真实解码结果、游标值及吸附采样点的间隔测量。截图没有后期修改。

## 验证边界

- 3 个默认跳过项是可选大型 BLF 压力测试；本次没有重复生成和运行 GiB 级数据测试。
- 未进行多窗口 GiB 级并行负载、长时间持续运行、多 DPI、屏幕阅读器专项验证。
- 项目仍只保存 DBC 路径和信号选择，不保存工作区布局、BLF 清单或测量标记。
- 本地 3.1.0 构建不代表已发布 GitHub Release。
